# Project Overview

## Project Name

NHS Hours Portal

## Idea Statement

A secure, student-friendly hour-tracking portal for NHS (National Honor Society) members to log and monitor their service requirements, connected to a Google Sheet backend for centralized data management. Members authenticate with their name and student ID, view personalized progress toward grade-specific hour requirements, and administrators can update the data source with a single protected action.

## Core Purpose

To replace manual hour tracking and spreadsheet management with a transparent, accessible interface that helps NHS members understand their service obligations, track progress in real time, and meet semester-based requirements without confusion or administrative overhead.

# Design Language

## Design Style

Clean, institutional interface with a focus on clarity and accessibility. The design borrows from educational dashboards and student portals: generous whitespace, a clear typographic hierarchy, and a single accent color for actionable moments. The layout prioritizes information density where needed (the progress summary) but avoids overwhelming the eye with unnecessary detail. Typography is restrained, sans-serif, and optimized for quick scanning. The overall effect is professional but approachable, like a well-designed university portal rather than a corporate SaaS tool.

## Design Tone

Straightforward, trustworthy, student-centric

## Design Mood

A quiet, well-lit workspace where students can quickly check their progress and understand what's required of them. The feeling is calm and reassuring, not bureaucratic or intimidating. There's a sense of clarity and order, like a well-organized bulletin board in a school hallway.

# User Stories

- As a student, I want to see my total service hours and remaining requirements at a glance so that I can quickly understand my progress toward the semester goal.
- As a student, I want to view my progress broken down by semester (first semester for seniors, second semester for juniors) so that I can focus on the current requirement.
- As a student, I want to see how many hours I've logged in the HW Center and Tutorial separately so that I can understand where my service is concentrated.
- As a student, I want to know whether I've completed required forms and paid my dues so that I can address any missing administrative items.
- As a student, I want to see when the data was last synced from the Google Sheet so that I trust the information is current.
- As an administrator, I want to update the Google Sheet data with a single button click so that I can quickly refresh member information without manual data entry.
- As an administrator, I want a confirmation step before updating the sheet so that I don't accidentally overwrite data.

# Tech Stack

This is a website built with Next.js.

## Build for

Website / web application

## Platform

Web (browser-based, responsive design for mobile, tablet, and desktop)

## Web Framework

Next.js 14+ (App Router) with TypeScript. Provides full-stack capabilities for authentication, API routes to sync with Google Sheets, and server-side rendering for fast page loads.

## UI Library

shadcn/ui + Tailwind CSS. shadcn/ui provides accessible form components (inputs, buttons, dialogs for the confirmation modal) and Tailwind CSS handles responsive layout and theming. The combination is lightweight, customizable, and aligns with the clean, institutional design language.

## Animation Library

tailwindcss-animate for simple transitions (button hover states, page fade-ins, modal slide-ups). No heavy animation library needed; the interface prioritizes clarity over motion.

## State Management

React Context API with useReducer for session state (logged-in user, student data). TanStack Query (React Query) for server state and Google Sheets data synchronization, with automatic refetching and caching.

## Database

Supabase (PostgreSQL) for storing student profiles, session tokens, and admin logs. Google Sheets acts as the source of truth for hour data; Supabase caches and indexes it for fast queries. Authentication tokens are stored server-side in Supabase, not in localStorage.

## Authentication

Custom authentication using Next.js middleware and server actions. Students log in with first name, last name, and student ID. On first login, the system checks the Google Sheet for the student's record and creates a Supabase account if eligible. Sessions are managed via secure HTTP-only cookies.

## Content Management System

Google Sheets (via Google Sheets API) as the source of truth for all student hour data. The admin update button triggers a server action that fetches the latest data from the sheet and syncs it to Supabase.

## Hosting

Vercel (native Next.js hosting, automatic deployments from GitHub, serverless functions for API routes, built-in environment variable management for sensitive credentials like Google API keys and Supabase connection strings).

## Additional Notes

Environment variables must include: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `GOOGLE_SHEETS_API_KEY`, `GOOGLE_SHEET_ID`, and `SUPABASE_SERVICE_ROLE_KEY` (server-side only). Rate-limit the admin update endpoint to prevent accidental repeated syncs. Implement CSRF protection on the admin confirmation button. All student data is encrypted at rest in Supabase; API calls use HTTPS only.

# Additional Notes

## Constraints

- Student data is read-only from the student perspective; all data originates from the Google Sheet. Students cannot manually log hours.
- The admin update button should have a rate limit (e.g. no more than once per minute) to prevent accidental repeated syncs.
- All authentication is session-based with HTTP-only cookies; no localStorage for sensitive tokens.
- The portal must comply with FERPA (Family Educational Rights and Privacy Act) guidelines. Student data should not be logged, shared, or exposed in error messages.
